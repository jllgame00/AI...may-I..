# AI...may I..?

2026 KHU AI Challenge 출품작 · 팀 **Ai...Khu**

**사용자 작업 분석 → 공식 기능·이용 조건에 따른 AI 회사 추천 → 추천 이유·제한사항 안내 → 맞춤 프롬프트 제공**를 연결하는 웹 MVP입니다.

## 문제 정의

사용자는 원하는 결과물이 있어도 어떤 AI 서비스에서 시작할지, 파일 처리·무료 이용·필요 기능을 어디까지 기대할 수 있는지 판단하기 어렵습니다. AI...may I..?는 작업과 필요한 기능을 먼저 정리하고, 확인된 조건과 미확인 범위를 구분한 뒤 바로 활용할 프롬프트를 제공합니다.

## 핵심 기능과 사용자 흐름

1. 자연어로 작업·자료·원하는 결과를 입력합니다.
2. 해석한 작업과 조건을 확인·수정합니다. 작업 카드는 여러 개 선택할 수 있고, 무료만·무료 선호·유료 가능을 고르거나 미정으로 둘 수 있습니다. 원문에 적은 금액 제한은 유지됩니다.
3. 조건이 확인된 회사를 최대 3개 먼저 확인합니다. 무료 선호를 선택하면 확인된 무료 경로를 먼저 고려하며, 같은 조건에서는 회사 이름순으로 표시합니다. 나머지 공동 후보·조건부·불일치 후보는 펼쳐 볼 수 있습니다.
4. 회사 상세에서 기능, 추천 이유, 제한, 무료 시작 가능 범위와 유료 기능 필요 여부, 실제 사용법·공식 링크를 확인합니다.
5. 회사·서비스를 선택해 작업 단계별 프롬프트를 편집·복사합니다. 복합 작업은 단계별 선택과 필요한 결과 인계를 유지합니다.
6. 실제 AI 서비스에서 직접 사용하고 결과를 검토합니다. 초안 재생성·이전 초안 복구·회사 변경 후 편집 내용 보존을 지원합니다.

**Deliverable First:** 설문지·보고서·대본·이메일의 완성본과 기획안·개요·목차를 구분합니다. 완성본 요청에 기획안만 요구하지 않으며, 복합 작업은 각 단계의 산출물을 분리합니다.

## 추천 근거와 한계

- 현재 카탈로그는 **12개 회사·13개 서비스·18개 플랜/미확인 경로**입니다. 공식 URL·확인일·적용 서비스/플랜 범위에 맞는 기능과 이용 조건을 사용합니다.
- PDF 업로드/분석/생성, XLSX 분석/생성, 설문 문항/실제 폼, 코드 작성/실행, 이미지 입력/생성, 검색/사실 검증을 구분합니다.
- 근거 부족·잘못된 범위·해결되지 않은 제한은 `unknown` 또는 조건부로 남깁니다. 등록된 미확인 후보를 가짜 데이터로 삭제하지 않습니다.
- 무료 플랜에 유료 기능을 적용하지 않습니다. 정확한 월 예산 판정은 통화·국가·세금·결제 주기까지 확인되는 경우에만 합니다. 화면은 상세 가격표보다 기능과 무료/유료 이용 조건을 안내합니다.
- 표시 순서는 **성능 순위가 아닙니다**. 자체 성능 점수·가중 총점·개별 모델 순위는 산정하지 않습니다. 성능 평가 데이터가 없어도 공식 기능과 사용자 조건에 따른 추천은 동작합니다.
- 카탈로그는 수동 검토 스냅샷입니다. 계정의 현재 권한·지역·잔여 사용량·변경된 요금은 사용자가 실제 서비스에서 확인해야 합니다.

자세한 판단 규칙은 [현재 추천 정책](docs/provider-recommendation-policy.md)을 참고하세요.

## 기술 스택과 구조

React 19 · TypeScript 5.9 · Vite 7 · Tailwind CSS 4 · lucide-react · Node.js 기본 테스트 러너 · Playwright Test.

```text
src/data/          Provider·Service·기능·이용 조건·공식 근거
src/lib/           요구 분석·추천·산출물 계약·프롬프트·초안 상태
src/components/    입력/조건·회사 비교/사용 안내·단계별 프롬프트 UI
tests/e2e/         Chromium PC·모바일 사용자 흐름 36개
scripts/           Provider 데이터 검증·수동 스냅샷 보존·복구
docs/              현재 정책·실행/검증 기록·제출용 정리 보고서
archive/           제품에서 분리한 과거 구현·연구·오프라인 평가 기록
evaluations/results/SURVEY-01/  사용자 제공 응답 8건의 보존본
```

별도의 서버·데이터베이스·LLM API 키는 필요하지 않습니다. 입력·선택·초안은 세션 메모리에 있으며 새로고침하면 초기화됩니다.

## 로컬 실행

Node.js **24 권장**(프로젝트 최소 22.18), npm을 사용합니다. 네트워크와 자식 프로세스 실행이 허용되는 일반 로컬 PowerShell에서:

```powershell
npm ci
npm run dev
```

Vite의 안내 주소에서 앱을 엽니다. GitHub Pages 프로젝트 경로 `/AI...may-I../`를 유지합니다.

```powershell
npm run build
npm run preview -- --port 4173 --strictPort
```

## 테스트 방법

```powershell
npm test
npm run typecheck
npm run data:validate
npm run setup:chromium
npx playwright test --list
npx playwright test
```

- 기본 테스트는 현재 제품의 단위·세션·SSR·데이터·격리 검증을 실행합니다. 사용자 피드백과 PPT 산출물 수정 후 **122개**가 통과했습니다.
- E2E는 기존 사용자 흐름 16개 + 설문 프롬프트/복사 6개 + 새 UI 흐름 14개, **총 36개**입니다. `tests/e2e/*.spec.ts`만 수집하며 Node 단위 테스트나 아카이브를 수집하지 않습니다.
- E2E 실행은 새 프로덕션 빌드 후 preview를 자동 시작·종료합니다. 별도 preview를 동시에 켜지 않습니다. 결과는 `.qa/provider-product-playwright.json`, 화면·trace는 `.qa/playwright-results/`에 저장합니다.
- 테스트 발견과 실제 통과는 다릅니다. 이번 관리 환경의 빌드·브라우저 실행은 `spawn EPERM`으로 차단됐으며, 최신 결과는 [PPT 프롬프트 수정 보고서](docs/pptx-prompt-fix-report.md)를 기준으로 확인합니다. 이전 `dist`를 이번 빌드 성공으로 간주하지 않습니다.

## 데이터 유지보수

```powershell
npm run data:validate
npm run data:refresh
npm run data:restore
# 수동 검토를 마친 전체 카탈로그 반입
node scripts/refresh-data.mts --import reviewed-provider-catalog.json
```

`data:refresh`는 현재 Provider 스냅샷을 검증·보존합니다. 외부 페이지를 자동 수집하거나 출처 확인일을 오늘로 바꾸지 않습니다. 잘못된 반입은 마지막 정상 데이터를 덮지 않으며, 복구는 Provider 전용 backup/seed를 사용합니다.

## 구현 완료 범위

자연어 규칙 분석·조건 수정, 공식 근거/예산 필터, 회사별 중복 없는 후보와 상세 사용 안내, 복합 작업 선택, Deliverable First 생성, 직접 편집·복사·재생성·복구, 카탈로그 검증·복구, 단위/SSR 및 E2E 시나리오가 구현돼 있습니다.

## 미구현·미검증 범위

이 앱은 AI 작업을 직접 실행하거나 원본 파일을 업로드받지 않습니다. 외부 AI 자동 호출, 로그인·구독·결제, 실제 설문 폼 배포, 파일 생성 완료 보장, 계정별 실시간 권한·한도 조회, 자체 회사 성능 평가·확정 순위 기능은 제공하지 않습니다.

복잡한 생략·부정 표현은 규칙 기반 분석의 한계가 있어 사용자의 해석 수정과 추가 사례 검증이 필요합니다. 실브라우저·모바일·OS 클립보드와 최종 프로덕션 번들은 실행 가능한 로컬 환경에서 재검증해야 합니다. 원문이 남아 있는 외부 서비스 응답 8건은 프롬프트 검토 사례이며 점수·회사 우위의 증거로 사용하지 않습니다.
