# 작업 추천 순위와 화면 배치 (2026-10-29)

이번 변경은 기존 후보 산출, 모델·플랜 매핑, 평가 관측값, 프롬프트·초안 보존 흐름을 유지한다. `src/lib/recommendationDisplay.ts`가 기존 비교 결과를 소비해 사용자 작업을 시작할 추천 순위를 별도로 계산한다. 기존 `decision.entries[].rank`는 벤치마크 집합 안의 원점수 순위이며 추천 순위로 복사하지 않는다.

## 적용 판단 기준

1. 기존 `primaryAccessCandidates`로 모델별 대표 경로를 얻는다. 이미 선택한 플랜 경로는 기존 방식대로 보존한다.
2. `taskReady`를 통과한 모델만 상단 추천 대상이다. 입력 형태 확정, 요청의 모든 필수 기능에 대한 출처 있는 지원, 모델·버전이 정확한 수동 선택 웹 경로가 모두 필요하다. 높은 평가 점수가 미확인 도구나 이용 경로를 상쇄하지 않는다. 서비스만 확인되고 모델이 미지정인 경우는 추천 모델 등수를 부여하지 않는다.
3. 작업 관련 평가는 기존 판단이 선정한 대표 비교 집합만 사용한다. 현재 직접 작업 관련성이 확보된 대상은 코딩(`fit >= 2`)이다. 추천 대상 **전부**의 정확한 모델 버전에 유효한 코딩 모델 평가가 있어야 하며 benchmark/version/unit/점수 방향이 일치해야 한다. 에이전트 실행 구성, 누락·비정상 점수, 다른 버전·도메인은 사용하지 않는다. 기존 비교 집합 검증을 재사용하고 다른 지표를 합산하지 않는다.
4. 이 조건이 충족되면 해당 집합의 점수 방향에 따라 작업 추천을 계산한다. `1 + 자신보다 나은 점수의 후보 수` 방식이며 같은 값은 공동 순위다(예: 1, 1, 3). 카드의 이유에 사용한 평가·버전·해당 후보의 원점수·점수 방향을 표시한다. 평가가 실제 웹 작업의 성공률을 직접 측정했다는 뜻은 아니므로 “원점수를 참고한 추천 판단”이라고 명시한다.
5. 공통으로 비교할 작업 평가가 없으면 필수 기능·웹 경로가 모두 확인된 모델들을 기능·경로 기준 공동 1위로 추천한다. 동등한 실행 근거가 있다는 판단이며 측정 성능의 동률을 뜻하지 않는다. 대상이 한 모델이면 1개만 표시하고, 실행 근거가 전혀 없으면 등수를 만들지 않는다. 누락된 평가를 0점 또는 낮은 성능으로 취급하지 않는다.
6. 가격, 유료·무료 여부, 모델명, 배열 순서는 **등수 계산에 사용하지 않는다**. 공동 순위 안에서는 기존 이름순 중립 표시를 유지한다. 상단에 최대 3개만 표시하며 나머지도 펼쳐서 선택 가능하다. 동등 후보가 3개를 넘을 때 접힌 위치가 낮은 등수를 뜻하지 않는다.

## 현재 설문 사례의 실제 판단

입력: 대학생 120명, 엑셀 설문 자료, 학년별 만족도 차이, 공부 시간·성적 관계, A4 4장 보고서. 필수 기능은 엑셀 분석·파일 첨부·코드 실행이다.

| 상단 실제 출력 | 플랜 | 판단 |
| --- | --- | --- |
| 추천 공동 1위 · Claude Opus 5.5 | Pro | 모든 필수 기능 및 정확한 웹 모델 경로 확인 |
| 추천 공동 1위 · Claude Sonnet 5.5 | Free | 모든 필수 기능 및 정확한 웹 모델 경로 확인 |

두 모델의 설문 분석을 직접 비교한 평가가 없어 둘 사이에 1위·2위를 정당화할 근거는 없다. AIME·HLE·코딩 원점수는 설문 추천 차등 순위에 사용하지 않았다. 플랜명은 정보 표시에만 사용했다. 두 카드에 “필수 기능·정확한 웹 경로가 확인돼 동등하게 추천합니다. 직접 성능 비교에 따른 순위는 아닙니다.”를 표시한다.

모델 미지정 서비스 4개(ChatGPT Free·Plus, Gemini Google AI Pro·미가입)는 “다른 서비스에서 시작하기 (4)”에 접어서 제공한다. 모델 확인이 필요하다는 상태·버튼 안내는 유지하며 Gemini의 코드 실행 미확인 등 후보별 제한은 카드에 남긴다. 추가 확인 모델도 기존대로 선택할 수 있다.

## 배치와 보존

- Grid의 `auto-fit`으로 후보 1개는 전체 너비, 2개는 2열, 3개는 가용 너비에 따라 최대 3열을 쓴다. 700px 이하에서는 1열이다. 후보 수를 고정값으로 가정하지 않는다.
- 엑셀 기능 설명은 그룹 소개에 한 번, 계정 활성화·파일 한도·사용량 확인은 공통 안내에 한 번 표시한다. 서비스별 추가 계정 안내도 공통 접기 영역에 모은다. 후보별 기능 미확인·웹 버전 미확인·FP8 제한은 카드에 남긴다.
- 선택 버튼 ID와 콜백을 유지한다. 접기는 기본 HTML `details`/`summary`와 기존 키보드 포커스 스타일을 사용한다. 이미 선택한 후보가 서비스·나머지 모델 접기 영역 안에 있으면 해당 영역을 열어 표시한다.
- App, 프롬프트 생성, 선택 상태, 편집·복구 로직, 원본 데이터는 수정하지 않는다.

## 검증 범위

`npm.cmd test`: 전체 193건 통과. 실제 비교 결과의 렌더링, 공동 추천, 최대 3개 상단 표시, 모든 후보 접근 보존, 계정·엑셀 설명 중복 제거, 개별 제한, 평가 누락·버전·도메인·agent 배제, 점수 방향·동률, 가격·이름·순서 독립성, 이용 경로 변경 시 재계산을 다룬다. 기존 선택·프롬프트·초안 보존 테스트도 통과했다. `npm.cmd run typecheck`와 `git diff --check`도 통과했다.

기존 `tests/browser-check.mjs`는 새 카드 구조를 반영하고 1440px의 2열·320px의 1열, 서비스 접기의 Enter 열기·닫기 확인을 추가했다. 이 브라우저 검증 스크립트는 구문 검사만 수행했으며 실제 실행 결과로 보고하지 않는다.

이 환경의 Vite 빌드는 esbuild 자식 프로세스를 시작하지 못해 `spawn EPERM`으로 중단된다. 실제 Chrome 제어는 자동 승인 검토에서 거절되어 PC·모바일 화면 캡처, 실제 키보드 조작·클립보드는 미검증이다. HTML 렌더링 검사와 타입 검사를 실제 브라우저 검사 또는 프로덕션 빌드 성공으로 간주하지 않는다. 데이터 재수집, commit, push, 배포는 수행하지 않는다.
