# 공개 평가 추정 사전 계획 — 2026-10-29, protocol-v1

이 문서는 첫 추정 실행 전에 작성했다. 현재 사용자 명세를 설계·구현 승인으로 사용하며 추가 승인, commit, push, 배포, 유료 평가를 수행하지 않는다. 기존 TypeScript/React와 저장된 공개 스냅샷을 사용한다.

## 관측과 연결

28개 모델·111건이라는 보고를 실제 런타임과 대조한다. 원자료는 수정하지 않는다. 각 관측의 정확한 릴리스, effort, 도구, 환경, 모델/에이전트 구분을 보존한다. 비교 그래프의 모델 측 정점은 모델 이름이 아니라 실행 구성이다. 평가 측 정점은 버전·문제 기간·실행 조건·평가 주체로 구분한다. 게시일 자체는 차단 조건이 아니다.

이미 검토된 `taskSourceGroups`, `declaredGroups`의 출처 표와 공개 조건이 완전히 일치하는 비교만 사용한다. 출처 표는 동일 환경의 독립 재현이라는 뜻이 아니다. 미공개 모델 설정은 해당 표 안에만 범위를 둔다. 이름·버전 없는 에이전트는 평가 간 연결하지 않는다. 평가 주체는 publisher와 구분한다. 서로 다른 표의 재게시 의심 동일 측정은 publisher·URL·게시일을 제외한 측정 식별자로 보수적으로 하나로 묶는다. 점수가 충돌하는 동일 식별자는 추정에서 제외한다. 새 모델·릴리스는 자동 상속하지 않는다.

## 방법과 대안

용어 명확화(기준 변경 아님): Qwen의 원문 Performance 표는 여러 평가 행과 동일 모델 열로 구성된 하나의 원문 표다. `taskSourceGroups`는 그 표의 LiveCodeBench 행과 Creative Writing 행을 별도 평가 노드로 정의한다. 명시된 non-thinking 모델 열은 같은 원문 표 범위의 보고 구성으로 연결한다. 미공개 effort의 DeepSeek 열은 평가 행을 넘어 연결하지 않는다. 동일 환경이 검증된 연결이 아니므로 제공사 보고 조건이라는 한계가 남는다. URL만 같다는 이유로 검토되지 않은 다른 표·모델을 연결하지 않는다.

문항별 응답·시행 횟수가 없어 IRT/Rasch를 사용하지 않는다. 서로 다른 척도의 원점수 회귀/백분율 합산도 피한다. 가장 단순한 대안으로 규제 Bradley–Terry 복합 목적함수를 사용한다. 각 표의 각 모델 쌍에 원점수 방향에 따라 y=1/0, 동점은 0.5를 배정한다. 이는 관측 정렬의 코딩이며 가상의 경기·문항·반복 시행이 아니다.

P(i>j)=sigmoid(theta_i-theta_j). 각 표의 모든 쌍 가중치 합은 1, L2 규제 lambda=0.25, theta 평균=0으로 식별한다. 정규 사전의 MAP와 유사하지만 복합 우도이므로 사후분포·신뢰구간으로 주장하지 않는다. 평가 난이도·변별도·제공사 보정 모수는 추가하지 않는다. 영역(coding/writing/reasoning 등)별 연결 성분과 일반(model only) 연결 성분을 각각 진단하되 영역 점수와 일반 점수를 합산하지 않는다. 일반 점수를 설문·한국어·저장소 작업의 실측 능력으로 표시하지 않는다.

## 고정 공개 기준

모든 조건을 충족해야 한다. 결과를 보고 바꾸지 않는다.

- 연결 성분에 구성 3개 이상, 서로 다른 평가 노드 3개 이상.
- 중복 제거된 관측 하나를 숨기는 leave-one-measurement-out 검증. 해당 관측을 포함한 모든 쌍을 학습에서 제거. 숨긴 모델과 비교 상대가 남은 학습 그래프로 연결된 경우만 예측. 6개 이상 관측 fold, 전체 fold의 80% 이상 평가 가능.
- 순서 확률의 Brier 오차가 무정보 기준선 p=0.5 대비 10% 이상 감소. 원점수 오차는 다른 척도 간 비교하지 않는다. 부가 기준선은 학습 내 구성별 Laplace 평활 승률의 차이를 이용한 예측으로 별도 보고한다.
- 비동점 쌍의 순서 정확도 65% 이상. 동점 예측은 반점 처리한다.
- 평가 하나를 통째로 빼는 분석에서 평가 가능한 구성 쌍 순서 보존율 80% 이상, 평가 제거의 80% 이상에서 전체 구성이 계속 연결됨.
- 각 표의 원점수 범위의 ±1% 결정적 작은 교란 20회에서 쌍 순서 보존율 90% 이상.
- 개별 공개 구성은 적어도 평가 3개에 관측되어야 한다. 단일 평가 주체 비중 75% 초과, 관측 부족은 불확실성으로 표시한다. 전체 조건을 통과해도 표 밖 모집단 일반화는 하지 않는다.

검증 fold는 독립 표본이 아니다. 같은 평가의 쌍과 관측은 상관되어 있으며 유의확률·표준 신뢰구간을 제시하지 않는다. leave-one-evaluation-out과 교란의 점수 범위는 **민감도 범위**일 뿐 신뢰구간이 아니다. 제공사 평가 선택 편향·미공개 judge·환경 차이를 해결하지 못한다.

## 환산·UI·갱신

통과한 성분만 0~100 지수 round(100*sigmoid(theta))로 표시한다(scale-v1). 중앙 기준 theta=0, 계수 1을 고정한다. 화면 후보 필터로 재적합하거나 min–max하지 않는다. 새 데이터로 재적합할 때는 버전 변경을 기록한다. 순위는 동일 성분에서 theta 기준 경쟁 순위. 점수차 3점 이내 또는 민감도 범위 중첩은 근소·동등 수준으로 표시한다. 데이터가 다른 성분 사이의 전역 순위는 없다. 일반 점수와 작업 지수의 합성 가중치는 도입하지 않는다.

기존 추천·기능 충족·웹 실행 상태는 보존한다. 검증된 추정 카드는 별도 영역에서 최대 3개를 먼저 표시하며 출처·방법·불확실성은 상세에 둔다. 미통과 시 보류 안내와 상세만 표시한다. API·에이전트 구성을 웹 성능으로 바꾸지 않는다. 원문·초안·단계별 프롬프트와 추가 확인 기본 접힘을 유지한다.

갱신/복구 후 동일 추정·검증을 실행하고 데이터 해시·모형/환산/프로토콜 버전·실제 계산 성공 시각·변경 기록을 저장한다. 성분별 검증 실패는 마지막 정상 공개 성분을 보존하고 오래된 데이터 표시. 새 버전/미연결 구성에 복사하지 않는다. 데이터 수집 시각과 계산 시각은 분리한다. 기존 Pages 설정은 수정하지 않는다.
