# 웹 채팅 입력과 복사 프롬프트 개선

2026-10-28. 이번 사용자의 두 요청을 함께 적용했습니다. commit·push·배포하지 않았습니다.

## 변경

- 입력에서 우선순위와 경로 선택을 제거하고 상태·타입·정책·테스트·현재 문서를 정리했습니다. 과거 세션의 speed/ease/API/CLI 값도 제거한 뒤 비교합니다. 첫 버튼은 후보 비교로 바로 연결합니다.
- 작업 품질은 관련 평가와 필수 기능 근거로 검토하며 종합 점수·근거 없는 순위·일괄 max 모드를 만들지 않습니다. 기존 매핑의 추론 설정을 유지합니다.
- 기본 후보는 웹 채팅 경로만 포함하고 정확한 버전/기능 미확인을 별도 표시합니다. API 네이티브 기능을 웹 기능으로 상속하지 않습니다. 모델 25개·평가 107건·원문 출처·기존 API/설치 매핑은 보존했습니다. CLI/에이전트 구성은 접힌 읽기 전용 참고로 남겼습니다.
- 선택 모델·플랜·가격·계정·권한·한도 안내는 화면에서 제공하며 복사 본문 생성에는 사용하지 않습니다. 사용자가 비교 작업에 직접 쓴 ChatGPT·Claude 등의 명칭은 제거하지 않습니다.
- 통계 분석/해석/보고서/검토는 각각 분석과 결과표/의미와 한계/앞 결과로 초안/수치·주장·출처·형식 대조를 요청합니다. 자료 부족과 처리 한계는 짧게 안내하며 파일 권한 확인으로 목적을 바꾸지 않습니다.
- 편집·재생성·복구·조건 변경의 초안 보존을 유지했습니다. 복사는 draft.text를 그대로 전달합니다. 선택 모델을 바꿔도 본문에 추천 정보가 붙지 않습니다.

## 생성 본문을 읽고 확인한 내용

아래는 현재 생성기를 실제 호출한 출력입니다. 단지 테스트 통과를 품질 근거로 삼지 않았습니다. 설문은 기술 통계와 가능한 집단 비교 결과표, 코딩은 재현·최소 패치·회귀 테스트, 홍보는 500자 완성 글과 필요한 모집 정보를 요청하는지 직접 읽었습니다. 처음 발견한 통계 질문의 남은 조사와 검토 단계의 보고서 형식 강제도 수정했습니다. 최종 보고서 분량/말투를 분석 단계에 강제하지 않으며 해석과 보고서는 필요한 앞 결과를 명시합니다.

규칙 기반 분류·조건 추출이므로 모든 중의적 문장을 이해하는 것은 아닙니다. 외부 AI 응답의 실제 분석 정확도·코드 실행·한국어 글 품질은 이번에 측정하지 않았습니다.

## 검증 결과

- `npm.cmd test`: 127개 통과, 실패 0. 새 목적·메타데이터 유출·원래 모델 비교명·API/CLI 세션 정규화·API 전용 배제·네이티브 기능 오상속 방지·기존 모드 보존·초안 보존·복사 전달 회귀 포함.
- `npm.cmd run typecheck`: 통과.
- `node --check tests/browser-check.mjs`: 통과. 브라우저 시나리오를 현재 단일 입력→웹 후보→단계→편집→복사·복구·320px 흐름으로 갱신했습니다.
- `npm.cmd run build`: esbuild 하위 프로세스 `spawn EPERM`으로 실패. `--configLoader native`도 Vite Windows 경로 처리의 하위 프로세스에서 같은 오류. 프로덕션 빌드 성공으로 보고하지 않습니다.
- 백그라운드 빌드 실행은 자동 승인 검토에서 `blocked by policy`로 거부됐습니다. 권한 상승을 요청하지 않았습니다.
- 로컬 소스를 TypeScript/Rollup으로 읽는 별도 QA 미리보기는 기동했으나 이는 프로덕션 빌드가 아닙니다. 브라우저 접근 호스트가 없고 Chrome 제어가 승인되지 않아 모바일 스크린샷·실제 브라우저 클립보드·내비게이션 시나리오는 미실행입니다. 정적 React 렌더와 세션 함수 회귀의 통과를 실제 모바일 화면 확인으로 대신 보고하지 않습니다.

별도 코드 검토에서 보고서 요청 뒤의 분석 질문 누락, 통계 기능 비교의 설문 오분류, 서비스 만족도 데이터의 비교 요청 오분류를 재현했습니다. 각 재현을 실패하는 테스트로 추가한 뒤 수정했고, 문장 순서와 서비스 명칭이 실제 설문 데이터 분석 목적을 바꾸지 않는지 다시 확인했습니다.

또한 조사 대상(예: 대학생 만족도)을 보고서 독자로 단정하지 않도록 독자 조건 추출을 수정했습니다. 명시적인 대상·독자 표현과 사용자 수정을 우선합니다.

## 실제 생성 예시

### 설문 분석

입력: 대학생 만족도 설문 CSV에서 학년별 평균과 표준편차, 집단 차이를 분석하고 A4 4장 보고서를 차분하게 작성해줘.

통계 분석

```text
분석할 질문: 대학생 만족도 설문 CSV에서 학년별 평균과 표준편차, 집단 차이를 분석

[설문 CSV·엑셀 파일을 첨부하고 문항·변수 정의·집단 구분을 적으세요]
먼저 변수 유형·표본 수·결측을 확인하고, 질문에 맞는 통계 분석을 수행해 주세요. 빈도·비율, 평균·표준편차 등 적절한 기술 통계를 계산해 결과표로 작성하고, 집단 차이·상관 분석은 자료와 가정이 충족될 때 수행해 주세요. 분석 방법·표본 수·단위와 검정 결과의 근거를 함께 적어 주세요. 자료가 없으면 먼저 요청하고 수치나 유의확률을 만들지 마세요. 요약 통계만으로 계산할 수 없는 항목은 필요한 원자료를 알려 주세요.
파일을 읽거나 계산을 실행할 수 없으면 그 한계를 밝히고, 텍스트·요약 통계 입력 또는 재현 가능한 분석 코드로 진행할 방법을 제안해 주세요.
```

결과 해석

```text
[앞 단계에서 확인한 통계표·변수 정의·계산 방법·남은 한계를 붙여넣으세요]
관찰된 결과와 가능한 해석을 구분해 주세요. 제공되지 않은 집단 차이·유의성·인과 관계를 단정하지 마세요. 해석의 근거 수치를 짚고 추가로 필요한 자료를 알려 주세요.
```

보고서 초안

```text
[앞 단계에서 확인한 통계표·결과 해석·한계·출처와 과제 지시를 붙여넣으세요]
조사 목적 → 자료·방법 → 결과 → 해석·한계 → 결론 흐름의 보고서 초안을 작성해 주세요. 제공한 내용만 사용하고 모르는 표본 수·방법·출처는 빈칸으로 남기세요. A4 페이지 수는 글꼴·여백 등 서식에 따라 달라지므로 임의의 글자 수로 보장하지 말고 서식이 없으면 확인해 주세요.

차분하게 써 주세요. 최종 분량은 A4 4장입니다. 결과 형식: 보고서.
```

검토

```text
[보고서 초안·원래 통계표·확인한 해석·출처·과제 기준을 붙여넣으세요]
수치 불일치·근거 없는 주장·논리 비약·요구사항 누락을 찾아 위치와 수정 제안을 표로 제시해 주세요. 자료에 없는 사실을 보완하지 마세요. 자동 검토로 정확성이 인증됐다고 말하지 말고, 사용자가 원자료와 직접 확인할 항목을 남겨 주세요.
보고서의 검토 기준: 분량 A4 4장 · 말투 차분하게 · 형식 보고서.
```

### 코딩

입력: React 장바구니의 수량 변경 버그를 수정하고 재현 테스트와 패치를 작성해줘.

기본 프롬프트

```text
React 장바구니의 수량 변경 버그를 수정하고 재현 테스트와 패치를 작성해줘.

입력 자료
[관련 코드와 오류 메시지를 붙여넣으세요]
자료가 없으면 내용을 추측하지 말고 필요한 자료를 물어봐 주세요.

수행 순서
1. 코드와 오류·기대 동작을 대조하고 버그의 재현 조건을 확인해 주세요.
2. 원인을 설명하고 기존 기능을 유지하는 최소 수정안을 작성해 주세요.
3. 재현 테스트와 회귀 테스트를 작성하고 실행 방법을 알려 주세요.

산출물은 변경 코드 또는 패치, 수정 이유, 테스트 방법과 실제 실행 결과입니다. 코드를 실행할 수 없으면 그 한계와 직접 검증할 절차를 적어 주세요.

답변 전 확인
수정 이유와 직접 실행할 테스트 방법을 포함해 주세요. 실행하지 않은 테스트를 통과했다고 말하지 마세요.
```

### 홍보 글쓰기

입력: 대학생에게 동아리 모집 홍보 글을 친근하게 500자로 작성해줘.

기본 프롬프트

```text
대학생에게 동아리 모집 홍보 글을 친근하게 500자로 작성해줘.

작성 조건
- 대상 독자: 대학생
- 분량: 500자
- 말투: 친근하게

핵심 매력과 참여 방법이 드러나는 완성 글을 작성해 주세요. 동아리·행사 이름, 모집 대상·일정, 신청 방법 등 꼭 필요한 정보가 없으면 먼저 물어봐 주세요. 확인되지 않은 혜택이나 실적은 만들지 마세요.

답변 전 확인
요청한 목적·형식·분량을 지켰는지 확인하고, 정보가 부족한 부분은 임의로 채우지 마세요.
```
