# 요청문·추천 카드 수정 보고서 (2026-10-28)

요청문 훼손, 과도한 카드 정보량, 확인 필요 후보의 구분을 수정했다. 모델·벤치마크 추가 수집은 하지 않았다. commit·push·배포를 하지 않았다.

## 원인과 수정

기존 경로는 interpretTask → buildPromptBundle/resolveConditions → extractConditions에서 분량을 `A4 4장`으로 추출한 다음, buildGuideBundle의 survey 분기에서 원문의 분량·말투·보고서 작성 구문을 삭제하고 나머지 조각을 재조합했다. 그 결과 `A4 4장짜리 보고서를 써야 해`가 `짜리`로 남고 `쉽게`도 사라졌다.

이제 원문과 별도로 작업·자료·조사 대상·자료 형식·연구 질문·설명 수준·최종 산출물을 구조화한다. 원문은 readonly 값으로 유지하고 구조화 결과는 freeze한다. 통계·해석에는 자료 조건과 두 연구 질문, 쉬운 설명을 유지한다. 최종 분량은 전체 요청과 조건에 보존하고 보고서 작성·검토에 반영한다. 미제공 표본 수·변수 정의·수치·질문·서식은 입력란이나 확인 대상으로 남긴다.

낯선 연구 질문이 알려진 질문 옆에 있어도 유지하며, 및/그리고/또한/알 수 없는 연결 표현에서 질문이 사라지지 않는 회귀 사례를 추가했다. 복사 본문은 추천 정보와 분리했고 앞 단계 자료를 넣을 위치를 구체적으로 유지했다.

## 보존·검증 결과

- 25개 모델 / 107건 평가 유지. 데이터·출처 파일과 vite.config.ts·Pages workflow 등 17개 보호 파일 SHA-256이 시작 시점과 모두 동일하다.
- 기존 미커밋 변경을 기반으로 수정했다. 사용자 초안의 조건 변경·재생성·복구·그대로 복사 동작은 회귀 테스트로 확인했다.
- `npm test`: 136개 통과, 실패 0개.
- `npm run typecheck`: 통과.
- `node --check tests/browser-check.mjs`: 통과.
- `npm run build`: 환경의 esbuild 프로세스 실행에서 spawn EPERM으로 실패. native config loader도 Windows 파일 경로 확인용 자식 프로세스 실행에서 EPERM으로 실패했다. 프로덕션 빌드 성공을 주장하지 않는다.
- 기존 인프로세스 소스 QA 번들러의 최신 코드 모듈 변환과 로컬 제공은 성공했다. 이것은 Vite 프로덕션 빌드나 실제 브라우저 실행 검증을 대체하지 않는다.
- PC·모바일 실제 화면 캡처는 확보하지 못했다. 별도 Chrome 실행은 접근 거부로 종료됐다. 기존 Google Chrome에 대한 컴퓨터 사용 도구 제어도 승인되지 않았다. 브라우저 자동 검사는 실행하지 못했으며 스크립트는 현재 구조와 설문 원문에 맞춰 보완했다.
- CSS는 PC 3열 / 중간 너비 2열 / 700px 이하 1열, 카드 높이 auto·최소 높이 0·상단 정렬로 구성했다. 기본 본문은 16px다. 실제 화면의 줄바꿈·높이·넘침은 환경 제한으로 미검증이다.
