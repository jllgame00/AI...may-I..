# PPT 산출물 계약 및 E2E 수정

2026-10-30. 기준 HEAD는 `aeba7cd`이며, 앞선 UI 개선의 미커밋 작업 20개 경로를 포함한 현재 파일 326개의 바이트와 테스트 기준을 먼저 보존했다. 기존 미커밋 작업을 초기화하지 않았다. commit·push·배포는 하지 않았다.

## 오류 원인

사용자가 보고한 기존 E2E는 36개 중 PPT PC·모바일 두 개에서 `/실제 발표자료/`를 기대했다. 실제 생성 본문은 ‘발표자료’와 ‘앞 단계의 확인한 자료’였다.

이는 기대 문자열만의 문제가 아니었다. `aiGuide.ts`의 슬라이드 단계가 고정 `instruction`으로 `deliverablePrompts.ts`의 기본 지시를 덮어써, 구체적인 파일 형식·전달 방식이 없었다. 단일 작업에도 앞 단계가 있다고 지시했다. 또한 프롬프트 생성에는 선택한 경로의 `slidesCreation` 확인 상태가 반영되지 않았다.

## 수정 내용

- 파일 생성(`slides`), 기획(`presentation_outline`), 실제 슬라이드별 텍스트(`presentation_content`)를 구분한다. 기획이나 내용만 요청하면 텍스트 작성 기능을 사용하고 PPTX 파일 생성을 강제하지 않는다.
- 산출물 계약에 선택적 `artifact`를 추가했다. 형식은 `pptx`/`text`, 전달 방식은 `downloadable-file`/`capability-check`/`inline-text`로 구분한다. 표시 문구와 실제 지시는 같은 계약에서 생성한다.
- 파일 생성은 기존 `compareCandidates`·`stageCandidate`로 선택 경로를 검사한다. 그 단계의 `slidesCreation`이 근거 범위에 맞게 `supported`인 경우에만 다운로드 가능한 PPTX 파일을 지시한다. 미선택·잘못된 선택·제외 경로·기능 미확인 경로는 지원 확인을 먼저 요청한다. 새로운 기능 근거를 만들지 않았다.
- 단일 작업은 사용자 주제·자료·조건에서 시작한다. 앞 단계 입력이 있는 경우에만 실제 인계한 결과를 요청한다. 전달되지 않은 결과를 알고 있다고 가정하지 않는다.
- 내용/기획과 최종 파일을 함께 요청하면 준비 텍스트를 파일 생성보다 먼저 배치한다. 같은 절에서 ‘내용을 채워서 PPTX 파일로 만들기’를 요청하면 중간 내용을 별도 최종 산출물로 오해하지 않는다.
- 설문 보고서 특화 흐름은 일반 보고서 단계만 대체하며, 별도로 요청한 슬라이드 내용 단계를 제거하지 않는다. 실제 존재하는 준비 단계만 PPTX에 인계한다.
- 기존 초안 보존·복구는 유지한다. 회사 변경 시 이전 편집 본문은 남고, 새 경로의 파일 생성 조건은 명시적 재생성으로 반영한다. E2E도 기존 안내와 재생성 동작을 거쳐 검증한다.

회사 추천 엔진, 공식 카탈로그·근거, 무료/유료·예산 판정 및 UI 컴포넌트는 이번 수정에서 변경하지 않았다. 슬라이드 내용만 요청한 경우의 작업 분류는 의도적으로 텍스트 작업으로 구분된다.

## 실제 프롬프트 전후 비교

입력: `인공지능 윤리를 주제로 발표할 PPT 자료를 만들어줘.`

수정 전 Claude 경로의 실행 지시:

```text
현재 단계 실행 지시
최종 산출물: 발표자료
앞 단계의 확인한 자료로 발표자료를 만들고 요구한 파일 형식으로 제공하세요. 대본만 작성하는 작업과 구분하세요.
이 단계는 위 산출물만 작성하고, 다른 단계의 작업을 함께 수행하지 마세요.
```

수정 후, 기존 카탈로그에서 파일 생성이 확인된 Claude 경로를 선택했을 때의 실제 생성 전문:

```text
작업 원문 (참고용; 아래 산출물 계약과 별도 수정 조건을 적용하세요)
<원문>
인공지능 윤리를 주제로 발표할 PPT 자료를 만들어줘.
</원문>

현재 단계 실행 지시
최종 산출물: 다운로드 가능한 PPTX(.pptx) 파일
사용자가 제공한 주제·자료·조건으로 발표자료를 제작하세요.
최종 산출물은 다운로드 가능한 편집용 PowerPoint PPTX(.pptx) 파일입니다. 실제 파일을 생성한 뒤 첨부하거나 실제 생성 파일의 다운로드 링크를 제공하세요.
슬라이드 제목·본문·레이아웃을 파일에 반영하고, 개요·대본·텍스트·생성 코드만 제공한 결과를 PPTX 파일이라고 말하지 마세요.
생성하지 않은 파일이나 가짜 다운로드 링크를 제시하지 마세요. 현재 계정에서 파일 생성이 불가능하면 그 한계를 밝히고 완료를 주장하지 마세요.
이 단계는 위 산출물만 작성하고, 다른 단계의 작업을 함께 수행하지 마세요.
```

같은 요청에서 파일 생성 기능이 미확인인 Gemini 경로를 선택해 재생성하면 실행 지시는 다음과 같다. 해당 서비스가 실제로 파일을 만들 수 없다고 확정하는 뜻은 아니다.

```text
현재 단계 실행 지시
최종 산출물: PPTX 파일 생성 지원 확인
요청된 형식은 PPTX(.pptx) 파일입니다. 선택한 서비스·이용 경로의 발표자료 파일 생성 지원 여부를 먼저 확인하세요. 확인 전에는 파일 생성·다운로드가 가능하다고 안내하거나 완료를 주장하지 마세요. 지원이 확인되지 않으면 그 한계를 밝히고 파일 생성이 확인된 경로를 선택하도록 안내하세요. 텍스트·대본·코드만 만든 결과를 PPTX 파일이라고 말하지 마세요.
이 단계는 위 산출물만 작성하고, 다른 단계의 작업을 함께 수행하지 마세요.
```

| 사용자 요청 | 계약 | 전달 방식 |
| --- | --- | --- |
| PPT 자료/실제 PPTX 파일 생성 | `slides`, `pptx` | 선택 경로의 지원 확인 후 파일 다운로드 지시 |
| PPT 기획안·발표 개요만 작성 | `presentation_outline`, `text` | 본문 내 개요, 파일 생성 요구 없음 |
| 슬라이드별 내용만 텍스트로 작성 | `presentation_content`, `text` | 실제 제목·본문 작성, 파일 생성 요구 없음 |
| 내용 작성 후 PPTX 파일 생성 | 준비 텍스트 → 파일 | 실제 준비 결과를 인계 |

위는 앱이 생성한 프롬프트다. 외부 AI에 입력하거나 실제 PPTX 파일을 생성한 실험은 수행하지 않았다.

## 테스트 변경과 결과

PPT E2E는 `/실제 발표자료/` 한 문구를 검사하는 대신 다음을 검사한다. 테스트 등록 수는 기존 36개를 유지한다.

- 충족 후보 선택 후 PPTX 형식·파일 첨부/다운로드 지시·허위 파일/링크 금지
- 단일 작업 단계 수 1개와 존재하지 않는 앞 단계의 부재
- 미확인 경로로 변경하고 재생성했을 때 지원 확인 계약으로 바뀌는지
- 기획/내용만 요청할 때 글쓰기 분류·텍스트 산출물·파일 생성 비강제

단위 회귀 7개는 `artifact`의 형식/전달 방식, 실제 선택 경로의 기능 검사, 미선택·미확인·제외 선택, 단일/복합 인계, 파일/내용/기획·명시 형식 우선순위, 혼합 요청 순서, 초안 보존·재생성·복구와 설문 보고서 특화 흐름을 검증한다. 실패하는 테스트를 먼저 실행한 뒤 수정했다. 문자열 기대값만 느슨하게 바꾸지 않았다.

이번 환경에서 36개 E2E가 통과했다고 주장하지 않는다. 사용자가 제공한 수정 전 34/36 결과와 이번 실행 결과를 구분한다. 일반 Windows PowerShell에서 빌드와 36개 E2E를 다시 실행해야 한다.

로그·비교 JSON·프롬프트 원문·수정 전 보존본은 `.qa/ppt-fix-*`에 있다. 이번 작업에서 수정 대상으로 허용한 기존 7개 파일 이외 319개는 시작 바이트와 동일하다. 이전 UI 개선의 미커밋 파일도 보존했다. 독립 검토에서 나온 내용/파일 혼합 요청 및 준비 단계 인계 문제를 회귀 테스트로 수정하고 재검토를 마쳤다.

## 이번 작업의 변경 파일

- `src/types.ts`: 내용 산출물과 구조화된 아티팩트 계약
- `src/lib/deliverables.ts`: PPT 파일/내용/기획 판별과 명시 형식 우선
- `src/lib/deliverablePrompts.ts`: 실제 파일/지원 확인/텍스트 계약 및 단일/복합 지시
- `src/lib/aiGuide.ts`: 선택 경로 기능 확인, 준비 → 파일 순서·인계, 존재하는 앞 단계만 참조
- `src/lib/presentationPrompt.test.ts`: 새 회귀 테스트 7개
- `tests/e2e/user-feedback.spec.ts`: 기존 PPT PC/모바일 테스트의 계약·단계 검증 강화
- `README.md`, `docs/README.md`, 현재 보고서: 최신 검사 수와 수정·검증 안내

프로젝트 전체 Git diff에는 이전 미커밋 UI 변경도 포함되어 있으므로 이번 변경 범위와 구분한다. 외부 AI 계정의 실제 권한·남은 한도·다운로드 파일 품질은 별도 확인 사항이다.
