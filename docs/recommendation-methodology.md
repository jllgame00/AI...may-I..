# 추천 방법론

정책 버전: `recommendation-v1.0.0`. 데이터 버전: `official-2026-10-21-audit-1`. 구현 전 정책을 확정하고 테스트로 검증한다.

2026-10-21 후속 [데이터 감사](benchmark-data-audit.md)에서 실제 결과 경로·이용 범위·현재 플랜 연결을 재확인했다. 추천 계산과 평가 비중은 유지했다. 아래 초기 조사에 더해 Arena의 별도 공개 데이터에는 CC-BY-4.0 표기가 있음을 확인했으며, 웹 리더보드 제한과 구별한다. 공개 투표 원자료를 현재 글쓰기 점수로 대체하지 않는다. 현재 수치 관측값·cohort·확정 모델 연결은 여전히 0개다.

## 목적과 범위

기존 React/Vite MVP의 입력 → 비교 → 단계별 선택 → 프롬프트 흐름을 보존한다. 서비스는 ChatGPT, Gemini, Claude의 개인 무료 플랜과 대표 월간 유료 플랜만 비교한다. 모든 플랜을 망라하지 않는다. 외부 AI 실행, 로그인, 결제, 자동 갱신, commit/push/배포는 범위 밖이다.

## 필터와 계산

1. 무료 전용이면 유료 플랜을 먼저 제외한다. 필수 기능이 `unsupported`이면 제외, `unknown`이면 조건부 후보다. 필수 기능은 사용자가 편집하며 모든 선택 단계에 적용한다.
2. 모델 ID·버전·추론 모드가 확인된 플랜 연결만 평가에 사용한다. 자동 라우팅, 마케팅 모델명, 모델군은 정확한 평가 모델의 근거가 아니다.
3. 총 적합도 = 벤치마크 B × 0.60 + 필요한 기능 F × 0.25 + 비용 C × 0.15. 소수 첫째 자리까지 표시한다. 서비스의 추천 정책이며 성공 확률이나 객관적 절대 성능이 아니다.
4. F: 요구 기능이 없으면 100, 모두 공식 지원이면 100. 하나라도 미확인이면 null. 미지원 후보는 점수 이전에 제외한다. 이 이진 항목은 필수 조건 충족의 확인 정도이지 기능 개수 경쟁이 아니다.
5. C: 무료 100. 유료도 가능에서는 확인된 월간 가격이 있는 유료 플랜도 100. 무료 우선에서는 확인된 월간 유료 플랜 50. 유료 금액·통화·주기 미확인은 null. USD와 KRW를 환산하거나 API 토큰 가격을 월 구독료로 사용하지 않는다. 가격 크기를 비교하는 정책이 아니라 예산 범주 적합성이다.
6. B: 아래 작업별 가중합. 각 평가의 원점수는 동일 평가 ID·버전·실행 모드·환경·에이전트 버전·단위·방향·기준일을 명시한 고정 cohort에서만 정규화한다. cohort의 모델 집합은 스냅샷에 고정하며 사용자의 예산 필터에 따라 바뀌지 않는다. 원점수 누락·중복·조건 불일치가 있으면 해당 cohort 전체를 보류한다. 모델이 2개 이상이어야 한다.
7. 정규화: 높을수록 좋으면 100 × (x-min)/(max-min), 낮을수록 좋으면 100 × (max-x)/(max-min). 모든 값이 같으면 50. 원점수가 실제 0인 경우는 유효하되 null을 0으로 대체하지 않는다. 고정 집합 내 상대값이므로 다른 스냅샷 간 점수 비교는 부적절하다.
8. 하나의 하위 평가라도 없으면 B=null. B/F/C 또는 모델 연결이 미확인이면 총점=null. 누락 가중치 재분배와 종합 지수 대체는 하지 않는다. 종합 지수는 설명용으로만 허용하고 구성 평가와 중복 합산하지 않는다.
9. 완전한 근거가 있는 후보, 필수 기능 확인 후보, 나머지 조건부 후보 순으로 표시한다. 동점은 무료 여부와 후보 ID의 코드포인트 순서로 결정한다. 총점 차이 3점 이내는 근소한 차이로 명시한다. 신뢰구간이 제공되면 함께 노출하며 우위의 통계적 확정으로 표현하지 않는다.
10. 기존 우선순위(품질/비용/쉬움/속도)는 프롬프트에 유지한다. 검증되지 않은 속도·사용성 수치로 정책 비중을 바꾸지 않는다.

비교 집합은 평가 슬롯마다 스냅샷 전체에서 정확히 하나여야 한다. 모델마다 다른 집합으로 정규화한 총점은 함께 순위를 매길 수 없으므로 여러 집합이 등록되면 해당 평가를 보류한다. SWE-bench는 에이전트 버전이 null인 경우에도 보류한다. 필수 기능의 지원 근거에는 출처 URL과 확인일이 모두 필요하다.

## 작업별 평가 선택

| 작업 | 평가 슬롯과 B 내부 가중치 | 선정 이유와 한계 |
|---|---|---|
| 자료 분석 | GDP.pdf 40%, AA-LCR 35%, AA-Omniscience accuracy 25% | 문서 근거 이해, 장문 추론, 사실 지식 정확성의 대리 평가. 실제 사용자 PDF 처리 성공을 보장하지 않음 |
| 발표 대본·글쓰기 | Arena Creative Writing 60%, IFBench 40% | 사용자 글 선호와 형식·지시사항 준수를 분리. 선호 점수는 사실 정확성이나 한국어 검증이 아님 |
| 코딩·버그 수정 | SWE-bench Verified 60%, SciCode 40% | 저장소 문제 해결과 과학 코드 작성의 대리 평가. SWE 에이전트 구성이 다르면 모델만의 효과로 비교하지 않음 |

AA 종합 Intelligence Index는 맥락 설명용이며 위 구성 평가와 합산하지 않는다. 한국어 품질 검증 데이터는 확보하지 않았다. 영어 또는 언어 혼합 평가를 한국어 품질 보장으로 표현하지 않는다. 기존 이미지 요청은 텍스트 콘셉트/프롬프트 설계 기능을 유지하지만 이번 점수 정책 대상은 아니다.

## 요청 해석과 복합 작업

기존 키워드 분류를 확장한다. 자료 분석, 코딩, 글쓰기 신호를 함께 찾아 단계별 평가를 적용한다. 기본 예시는 자료 분석 → 발표 구조 → 대본 작성의 세 단계다. 인식되지 않거나 선택적 표현(또는/아니면/할까 등)이 있으면 작업 확인을 요청하고 자동 확정하지 않는다. 사용자는 입력 화면에서 작업·순서·필수 기능을 수정할 수 있다. 텍스트를 바꾸면 이전 수동 해석은 초기화한다. 재분석 시 후보와 모든 단계 배정을 새로 생성한다.

## 수동 갱신 절차

### 독립적인 과거 모델 평가 (2026-10-21 추가)

현재 추천용 관측값과 별도로 [공개 투표 재분석 방법·실행 기록](arena-public-votes-methodology.md)을 추가했다. `arena-human-preference-140k`의 고정 revision을 읽는 처리 도구와 추천 결과의 “모델 평가 참고” 영역이 연결되어 있다. **현재 환경에서는 실제 다운로드·계산 미완료로 결과 JSON이 없다.** 플랜 연결 미확인은 독립 모델 평가의 표시를 막지 않는다. 정확한 모델 ID만 대조하며 과거 전체 선호도를 최신 모델·특정 작업·현재 서비스 성능으로 대체하지 않는다. 계산된 JSON은 `recommend.ts` 또는 60/25/15 입력에 전달하지 않는다.

이하 1~6은 **현재 통합 추천용 데이터** 갱신 절차다. 독립 공개 투표 집계는 위 문서의 별도 명령과 버전을 따른다.

1. 공식 페이지를 직접 확인하고 확인일·지역·주기·제한을 기록한다. 미확인값은 null/unknown 유지.
2. 벤치마크의 공개 번들 재배포 권한을 먼저 확인하고 허가 URL/라이선스를 기록한다. AA API는 허가된 갱신 환경에서만 사용한다. 키는 프론트엔드, VITE 변수, JSON, git에 절대 넣지 않는다. 401/403/접근 제한을 우회하지 않는다.
3. 정확한 모델 ID·버전·추론 모드와 플랜 연결의 공식 근거를 확보한다. 한 플랜에 여러 모드가 있으면 개별 연결/후보로 작성한다.
4. `src/data/recommendationSnapshot.ts`의 models/observations/mappings/cohorts를 갱신한다. 평가 기준일, 신뢰구간, 표본 수가 없으면 null. 재배포 허가가 없는 수치는 넣지 않는다.
5. cohort 버전과 관측 조건을 검토하고 데이터 버전을 올린다. 정책/가중치 변경 시 정책 버전도 올린다. 예시 수치는 `src/lib/fixtures/`에만 둔다.
6. `npm test`, `npm run typecheck`, `npm run build` 및 PC/모바일 흐름을 확인한다. 별도 승인된 릴리스 절차로 공개한다. 이번 구현에는 자동 갱신·리더보드 런타임 요청을 추가하지 않는다.
