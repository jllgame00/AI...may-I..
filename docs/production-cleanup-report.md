# 최종 제품 정리 및 검증 결과

2026-10-29, 기준 커밋 `0f79525`. 이번 작업은 기존 미커밋 Deliverable First 구현과 실제 응답 보존 작업 위에서 진행했다. commit·push·배포는 하지 않았다.

## 정리 결과와 보존 경계

현재 제품은 **사용자 작업 분석 → 공식 기능·이용 조건에 따른 AI 회사 추천 → 추천 이유·제한사항·사용 안내 → 맞춤 프롬프트**다. 새 기능, 회사별 성능 점수, 평가 루브릭이나 순위를 추가하지 않았다.

시작 시 생성 파일을 제외한 316개 파일(추적 293개, 기존 미추적 23개)을 전수 분류했다. 파일별 import, 런타임 연결 여부, 참조와 SHA-256, 원래 경로와 이동 경로는 [정리 목록](production-cleanup-manifest.json)에 있다. 이 수는 시작 시점의 목록이며 이번 작업에서 새로 만든 안내·검증 파일은 별도다.

| 분류 | 파일 수 | 처리 |
| --- | ---: | --- |
| KEEP | 60 | 활성 구현·공식 데이터·기존 사용자 작업을 원래 바이트로 유지 |

| ARCHIVE | 236 | 기존 아카이브 156개 유지, 추적 파일 80개를 비활성 기록으로 이동 |

삭제·이동은 기존 추적 파일에만 수행했다. 기존 미추적 23개는 모두 원래 경로와 바이트를 유지했다. 사용자 제공 DOCX 두 개는 현재 구현과의 차이가 있어도 원본 자료이므로 유지했다. `.qa/production-cleanup-before/`에는 시작 시점 파일별 보존본과 해시, 추천 비교 기준을 보관했다. 기존 Git 이력과 미커밋 작업을 초기화하지 않았다.

80개 이동 파일의 원본 SHA-256은 [보존 목록](../archive/production-cleanup-preservation.json)에 있으며 기본 테스트에서 검사한다. 모든 이동 파일과 기존 유지 파일의 바이트를 작업 전 목록과 대조했다. 기록용 코드의 상대 import와 문서 링크는 당시 트리 기준으로 보존했다. 현재 위치에서 독립 실행 가능한 평가 프로젝트가 아니며, 실행 경로를 복구하지 않았다. 원래 경로는 정리 목록으로 찾는다.

`package.json`에서 `evaluation:*` 6개, `report:providers`, `test:browser`, `qa:preview`를 제거했다. 현재 앱·기본 테스트·타입 검사·운영 명령은 이 비활성 코드에 의존하지 않는다.

- 빈 `models: []`와 그 호환 타입은 카탈로그 반입·검증 스키마 및 모델 데이터와의 독립성 테스트에 사용하므로 유지했다. 모델 레코드나 점수·모델 추천 경로는 없다.

- 과거 점수와 합성 평가 자료는 바이트를 보존한 비활성 아카이브에만 남겨 두었다. 활성 회사 성능 점수나 임의 순위를 생성하는 경로는 제거했다.
- 선언된 npm 의존성은 제품·빌드·타입·테스트에서 모두 사용한다. 추측으로 제거하거나 새 라이브러리를 추가하지 않았다.

## 기능 보존 검증

작업 전후 16개 입력에 대해 다음을 대조하여 동일함을 확인했다. 설문·XLSX·PDF·대본·코드·이미지·무료 조건·복합 작업, 문서 개요, 파일 한도 경계와 검색 필요 여부를 포함했다.

- 요구사항과 필수/선호 기능, 기능별 근거·제한·예산 상태
- 회사·서비스·플랜 선택과 대안, 추천/나머지/조건부/제외 후보의 순서
- 단계별 회사 후보와 모든 플랜 검사 결과
- 단계 ID·작업·출력 설명과 생성된 프롬프트 전문

삭제한 미사용 점수 필드와 제품 방향에 맞춰 바꾼 공통 안내 문구는 비교 대상에서 제외했다. 추천 결정이나 사용자 프롬프트 내용은 달라지지 않았다. 자연어 입력, 조건 수정, 회사 선택, 복합 작업 단계 선택, 프롬프트 편집·복사·초안 복구와 사용 안내를 위한 기존 테스트를 유지했다. 실행 그래프는 로컬 파일 25개이며 평가·아카이브로 연결되지 않는다. 활성 상대 import 오류와 진입점에 연결되지 않은 제품 TypeScript 모듈은 발견되지 않았다.

Windows PowerShell, Node.js 24.13.0 환경에서 실행했다. 빌드와 E2E의 `spawn EPERM`은 관리 실행 환경의 자식 프로세스 제한으로 구분한다. 프로덕션 번들 생성 및 브라우저 동작이 이번 환경에서 통과했다고 주장하지 않는다. 실행 로그와 비교 결과는 로컬 `.qa/production-cleanup-*.log`, `.qa/production-cleanup-verification.json`에 있다.

현재 안내 문서 8개의 로컬 링크 39개는 모두 존재한다. 활성 상대 import 오류·사용되지 않는 제품 TypeScript 모듈이 없으며, TypeScript의 `noUnusedLocals`·`noUnusedParameters` 검사와 `npm ls --depth=0`도 통과했다. `git diff --check`는 종료 코드 0이다. 과거 바이트 보존 문서의 당시 경로 참조는 현재 안내 링크와 구분한다. 독립 검토에서도 데이터 손실, 추천 결정 변경, 제품 테스트 누락이나 활성 참조 오류는 발견되지 않았다.

## 제출 전 필수 확인

일반 로컬 PowerShell에서 다음을 실행해 **새 프로덕션 번들과 E2E 22개 통과**를 확인해야 한다.

```powershell
npm run build
npx playwright test --list
npx playwright test
```

실제 서비스에서 선택한 계정의 권한·남은 사용량·지역/플랜 제한은 사용자 확인 대상이다. 외부 AI 응답 품질을 자동 보증하지 않으며, 자연어 부정/생략 표현과 복잡한 작업은 사용자 조건 수정과 추가 검증이 필요하다. 아카이브는 제출 기능이 아니고 과거 기록이다. Git 이동은 staging하지 않았으므로 상태에는 원래 경로 삭제와 새 아카이브 미추적 추가로 표시된다. 최종 변경 검토와 커밋·배포는 별도 사용자 요청 범위다.
