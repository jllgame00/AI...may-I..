# 비교 집합과 작업 추천 범위 정정

사용자 요구사항을 구현 기준으로 삼는다. 기존 25개 모델·111건 평가·출처·선택 ID·웹 mode·편집 초안은 보존한다. commit/push/배포 금지.

## 확인한 원인

`taskRanking.ts`는 source group을 순회하다 첫 집합에서 즉시 반환한다. 이로 인해 후속 완전 조건 비교와 다른 제공사 자료가 검토되지 않는다. `available()`도 웹 후보만 대상으로 삼아 API/경로 미확인 후보를 대표 평가 검토에서 제외한다. `functionalProfiles`의 고정 배열과 인덱스가 설문·글쓰기의 앞뒤를 결정한다. ‘알고리즘 문제 풀이’는 기존 키워드가 인식하지 못한다.

## 정책

1. 입력에서 algorithm/application/repository/unspecified를 추론한다. 알고리즘·코딩테스트 → algorithm, React/앱 기능 → application, 오류 수정·기존 저장소 → repository. 혼합 요청은 기존 코드 수정 요구를 우선한다. 수정은 기존 해석 요약에만 둔다.
2. 등록된 모든 모델과 관련 평가를 검토하고 집합을 모두 구성한다. 대표 선정: 작업 관련성 → 비교 조건 명확성 → 고유 비교 모델 수 → 양쪽에 실제 평가일이 공개된 경우 시점. 동률 집합은 안정된 표시 ID로 결정하며 다른 집합도 보존한다. 점수·제공사·최신 모델 이름·가격·웹 권한은 대표 선정 기준이 아니다.
3. 알고리즘은 LiveCodeBench, 앱/웹은 CursorBench, 저장소 수정은 DeepSWE/SWE-bench 등의 관련성을 우선한다. LiveCodeBench는 앱/저장소의 대표 순위로 사용하지 않는다. 숫자는 대표 평가 내부의 원점수 순위로만 표시한다.
4. Qwen 게시 LiveCodeBench v6는 평가명/2025.02~05/Qwen/실제 포함 모델 수를 분리한다. 전체 LCB 리더보드·등록 모델 전체 순위라고 부르지 않는다.
5. 대표 평가, 다른 평가의 동등 대안, 관련 직접 비교 부족 후보를 별도로 제공한다. 전체 모델별 빠진 이유와 다른 집합은 펼침으로 확인한다. API/미확인 경로 평가는 읽기 전용이며 웹 선택 후보를 임의로 확장하지 않는다.
6. 설문·글쓰기는 근거가 있는 모델을 모두 동등 검토 후보로 제공한다. 구체적 평가 → 추론한 도움 → 직접 검증하지 못한 범위를 설명한다. 한국어 직접 측정이 없는 점수로 한국어 작성 순위를 만들지 않는다.

## 작업·검증

- 실패 테스트: 네 실제 입력, subtype 수정, 전체 집합 탐색/역순 불변, Qwen 게시·기간·실제 모델 수, Sonnet/Opus/Terra 대안과 Astra/Sol 제외 사유, 동점·누락·지수/agent 혼합 거부, 무순위 동등 후보, 기존 선택/초안 보존.
- `codingIntent.ts`, `evidenceComparisons.ts`, `taskRanking.ts`로 분리하고 타입/aiGuide/해석 요약/결과 카드를 연결한다.
- 전체 테스트·타입·빌드를 실행하고 가능한 화면 검증을 한다. 네 입력의 실제 모델 수·평가·제외 이유·렌더된 카드 문구를 보고서에 기록한다.
