# 사용자 피드백 UI 개선 계획

사용자 요청의 네 가지 UI 변경과 A/B/C 검증 범위에 한정한다. 기준 커밋 `aeba7cd`, 시작 Git 상태는 깨끗하다. 기존 React·CSS·네이티브 라디오/체크박스를 재사용하고 직접 구현한다. 새 라이브러리·데이터·모델·회사·배포는 추가하지 않는다.

- [x] 기준 파일과 8개 기존 요청의 추천·프롬프트 결과를 보존한다.
- [x] 회귀 테스트를 먼저 추가해 무료 선호/미정 구분, 금액 보존, 미확인 무료/기능 배제, PPT 파일/기획 구분의 실패를 확인한다.
- [x] `Budget.preferFree?: boolean`과 선택 변경 helper를 추가한다. 기존 `freeOnly`, 금액·통화·국가는 보존한다. 무료 선호에서만 근거가 있는 무료 경로를 먼저 고려한다. 기능 판정·무료 필수·예산 상한·unknown 규칙은 유지한다. 요청 예산은 부분 override로 저장해 원문 숫자 수정도 반영한다.
- [x] 예시 안내, 예산 3개 라디오+미정 동작, 다중 작업 카드, 접힌 필수 기능 목록, 서비스명 중심 제목을 적용한다. 원문 숫자 예산은 읽기 전용으로 남긴다.
- [x] PPT 표현 인식과 PPT 개요/내용 기획 구분을 보완한다. 공식 이미지/슬라이드 파일 기능이 미확인인 경로의 사용 안내는 확인부터 요청한다.
- [x] 기존 E2E의 예산 선택 검증을 새 UX로 바꾸되 기능·무료 판정 검사를 유지하고 새 사용자 흐름/키보드/다중 선택/초안 보존/화면 검증을 추가한다.
- [x] 단위·타입·데이터·build·E2E·PC/모바일 화면 검증을 시도하고, 실행 환경 제한을 실제 통과 결과와 구분해 보고한다. 독립 검토의 PPT 경계 문제를 회귀 테스트로 수정한다.
- [ ] 일반 실행 환경에서 프로덕션 빌드와 E2E 36개를 통과시키고 PC·모바일 스크린샷을 검토한다. 현재 build/E2E는 spawn EPERM, 화면 도구는 브라우저 연결 불가·Chrome 접근 미승인으로 차단됐다.

검토 초점: 미정에 임의 선호가 선택되지 않음, 무료 선호가 유료 허용/미정과 구분됨, 선택 변경 시 원문 금액 손실 없음, 무료 근거 없는 경로 우선 금지, 지원 기능과 생성 프롬프트/사용 안내 일치, 회사/서비스 변경 시 편집 초안 보존.

commit·push·배포 및 `.git` 변경은 수행하지 않는다.
