# 작업별 근거 기반 추천 구현

사용자가 제공한 상세 요구사항을 구현 기준으로 사용한다. 현재 미커밋 변경과 웹 채팅 선택·단계별 프롬프트·초안을 보존하며 commit/push/배포하지 않는다.

## 설계 선택

- 전체 평가를 합산하는 점수 대신 작업별 단일 비교 집합을 선택한다. 원점수·공식 지수를 그대로 쓰고 공동 순위는 competition ranking(1, 1, 3)으로 계산한다.
- 기존 107건을 유지하고 Qwen 공식 표의 동일 기간 코딩 비교 열 2건과 창작 비교 열 2건을 별도 관측으로 보완한다. 출처가 선언한 표 비교와 완전한 동일 실행 조건 비교를 구분한다. 미공개 조건을 같다고 추정하지 않는다.
- 코딩은 LiveCodeBench v6(2025-02~05)의 모델 평가를 우선 사용한다. 창작 요청은 Creative Writing v3를 사용하되 한국어·요청 적용은 추론임을 표시한다. 일반 글쓰기는 버전·judge가 불명인 WritingBench를 강제 순위화하지 않는다.
- 설문은 StatQA와 기존 수학·추론·문서 관련 자료를 검토하되 현재 모델 직접 결과 부족으로 숫자 순위를 만들지 않는다. 확인된 기능의 용도에 따라 우선 검토 후보를 고르고 부족 근거는 목록 상단에서 한 번 설명한다.
- 성능과 웹 이용권한을 분리한다. 기본 선택 ID와 mode는 바꾸지 않고 평가 설정을 별도 필드로 표시한다. 가격은 읽지 않는다.

## 구현 순서와 검증

1. 실제 compareCandidates 결과에 대한 회귀 테스트를 먼저 추가한다. 코딩 상위 3, 점수 변경, 동점, 누락, 버전/모드/agent/출처 혼합 거부, 배열 순서·가격 독립성, 설문 코딩 배제, 글쓰기 fallback을 확인한다.
2. 출처별 비교 집합과 작업 정책, 순위/검토 결과 타입을 추가하고 compareCandidates에 연결한다. 기존 상세 카탈로그는 유지한다.
3. 결과 화면 첫 영역에 우선 추천과 대안 2개를 표시한다. 순위/공동 순위, 모델/평가 설정, 이유, 원점수, 관련성·한계와 별도 접근 상태를 노출한다. 나머지는 접어서 제공한다.
4. 렌더 테스트, 전체 테스트, 타입 검사, 빌드를 실행한다. 가능하면 로컬 브라우저에서 실제 순서·선택·단계별 초안 보존을 검증한다. 실제 실행 결과와 연구의 한계를 보고서에 기록한다.

## 검토 초점

동점의 선두를 단독 최고로 표현하지 않기, 미평가를 0점으로 처리하지 않기, 서로 다른 버전/기간/effort를 등록된 비교 범위 밖에서 섞지 않기, 필수 기능/계정 권한이 성능 점수를 바꾸지 않기, 일반 글쓰기와 한국어 창작의 적용 범위를 구분하기.
